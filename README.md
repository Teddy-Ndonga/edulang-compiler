# EduLang Compiler

EduLang is a small educational programming language developed in Python. This project implements a compiler that translates EduLang source code (`.edu` files) into executable Python code.

The project demonstrates the fundamental stages of compiler construction, including lexical analysis, syntax analysis, semantic analysis, and code generation.

## 1. Project Objectives

The main objectives of this project are to:

- Design a simple programming language with its own syntax.
- Implement a lexer to convert source code into tokens.
- Implement a parser to validate syntax and construct an Abstract Syntax Tree (AST).
- Implement a semantic analyzer to check variable declarations and data types.
- Generate equivalent Python code from EduLang programs.
- Execute compiled programs.
- Demonstrate the language using practical programming examples.

## 2. Technologies Used

## 4. How the Compiler Works

EduLang follows a series of compilation stages.

### Stage 1: Lexical Analysis

**File:** `src/lexer.py`

The lexer reads the EduLang source code character by character and groups characters into meaningful units called tokens.

For example:

```text
LET age = 20
PRINT age
```

The lexer identifies tokens such as:

- `LET` – variable declaration keyword.
- `age` – identifier.
- `=` – assignment operator.
- `20` – number literal.
- `PRINT` – output keyword.

**File:** `src/tokens.py`

This file defines the available token types using Python's Enum class.

It also defines the Token data class, which stores:

- Token type.
- Token value.
- Line number.
- Column number.

### Stage 2: Syntax Analysis

**File:** `src/parser.py`

The parser receives the tokens generated by the lexer and checks whether they follow EduLang's grammar.

It organizes valid statements into an Abstract Syntax Tree (AST).

For example:

```text
LET total = 100
PRINT total
```

The parser recognizes these as a variable declaration followed by a print statement.

**File:** `src/ast_nodes.py`

This file defines the different AST node structures used by the parser.

Examples include:

- `Program`
- `LetStatement`
- `SetStatement`
- `PrintStatement`
- `InputStatement`
- `IfStatement`
- `WhileStatement`
- `NumberLiteral`
- `StringLiteral`
- `BinaryExpression`

Each node represents a particular programming construct.

### Stage 3: Semantic Analysis

**File:** `src/semantic_analyzer.py`

The semantic analyzer checks whether a program makes logical and type-related sense.

It performs checks such as:

- Ensuring variables are declared before they are used.
- Preventing assignments to undeclared variables.
- Checking data type compatibility.
- Validating expressions and conditions.

For example, attempting to assign a decimal value to an integer variable results in a semantic error.

### Stage 4: Code Generation

**File:** `src/code_generator.py`

After successful semantic analysis, the code generator translates the AST into equivalent Python code.

For example, EduLang:

```text
START
    LET number = 10
    PRINT number
END
```

Generates Python:

```python
number = 10
print(number)
```

The generated Python code preserves the program's operations and control flow.

### Stage 5: Compilation Management

**File:** `src/compiler.py`

This file connects the different compiler stages.

It coordinates the compilation process in the following order:

1. Create the lexer.
2. Generate tokens.
3. Pass tokens to the parser.
4. Construct the AST.
5. Perform semantic analysis.
6. Generate Python code.
7. Return the generated code.

### Stage 6: Command-Line Interface

**File:** `src/main.py`

This file provides the command-line interface for using the compiler.

It allows users to:

- Specify an EduLang source file.
- Choose an output Python file.
- Compile source files.
- Execute generated Python programs using the `--run` option.
- Receive error messages when compilation fails.

## 5. EduLang Language Features

EduLang supports the following programming constructs:

| Feature | Syntax |
|---|---|
| Program start | `START` |
| Program end | `END` |
| Variable declaration | `LET` |
| Variable assignment | `SET` |
| Output | `PRINT` |
| User input | `INPUT` |
| Conditional statement | `IF ... THEN` |
| Alternative condition | `ELSE` |
| Loop | `WHILE ... DO` |
| Integer values | `10` |
| Decimal values | `10.5` |
| String values | `"Hello"` |
| Boolean values | `true`, `false` |
| Comments | `# comment` |

### Supported Operators

**Arithmetic operators**

- `+` Addition
- `-` Subtraction
- `*` Multiplication
- `/` Division
- `%` Modulo

**Comparison operators**

- `==` Equal to
- `!=` Not equal to
- `>` Greater than
- `<` Less than
- `>=` Greater than or equal to
- `<=` Less than or equal to

### Example Program

```text
START
    LET age = 20

    IF age >= 18 THEN
        PRINT "You are an adult."
    ELSE
        PRINT "You are a minor."
    END IF
END
```

## 8. Running EduLang Programs

You can compile an EduLang source file using:

```bash
python -m src.main examples/grade_calculator.edu
```

The compiler generates a Python file alongside the source file:

```text
examples/grade_calculator.py
```

To compile and execute a program in one command:

```bash
python -m src.main examples/grade_calculator.edu --run
```

Run the simple calculator:

```bash
python -m src.main examples/simple_calculator.edu --run
```

### Specifying a Custom Output File

You can also specify where the generated Python file should be saved:

```bash
python -m src.main examples/grade_calculator.edu -o output/grade_calculator.py
```

## 10. Error Handling

EduLang detects several types of errors during compilation.

**Lexical errors:** Invalid characters or unsupported tokens.

**Syntax errors:** Incorrect language structure or invalid statements.

**Semantic errors:** Undeclared variables and incompatible data types.

**Code generation errors:** Errors encountered while translating unsupported AST structures.

The compiler reports errors rather than generating a program from invalid source code.
